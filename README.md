## Возможности

- Девять вкладок FB Tools: Доступ, Rename кабинетов, Kill, Billing, Каталог, Права, Партнёрство, Удаление, Пиксель.
- Billing: адрес Manchester/Wilmington и три часовых пояса, привязка и основная карта. Как у коллеги, новый адрес по умолчанию — Manchester, NH 03104.
- Удаление каталогов по списку «оставить/удалить» и DISABLED кабинетов из BM. Это отдельная функция от Kill Account.
- Привязка пикселя к кабинетам с проверкой видимости и выдача системному пользователю.
- Отдельная закладка LeadingCards: выпуск, закрытие/пауза карт и повторное получение реквизитов. «Панелька Ленина» сохранена.

## Rename каталогов

Два столбца старых и новых числовых **названий** сопоставляются построчно. Скрипт ищет настоящий `catalog_id` по старому названию внутри выбранного BM, пропускает отсутствующие и неоднозначные имена, проверяет пары и подтверждает новое имя чтением после записи. Внутренний ID не меняется.

Постоянные ID успешно переименованных каталогов можно скопировать отдельной кнопкой. После Rename план удаления сбрасывается. Очистка блокируется, если хотя бы одна строка списка не найдена; неоднозначные имена на удаление нужно заменить точными ID. Перед запуском повторно сверяются список, названия и отношения каталогов к BM. Изменение BM, режима или списка сбрасывает план. DISABLED перепроверяется непосредственно перед удалением кабинета.

## Порог автоматического списания — You'll pay when

В **Billing → Attach card**:

1. Вставьте столбцы кабинетов и карт.
2. Выберите 50, 100 или произвольную сумму для USD (по умолчанию **100 USD**).
3. Нажмите **Проверить валюты и суммы**. Скрипт читает `account_id,currency`, не меняя оплату. Для другой валюты введите сумму отдельно в строке; конвертации нет.
4. Запустите **Run cards**. Перед привязкой каждой карты повторно проверяется валюта; настройка порога использует штатный диалог **Billing date and threshold → Enter an amount → Save**.
5. Подтверждённым считается только совпадение фактического порога после обновления страницы. Ошибка Meta, несовпадение валюты, недоступный диалог, предел `min/max` и неподтверждённый результат отображаются отдельно от результата привязки.

По умолчанию при неподтверждённом пороге пакет останавливается **до привязки карты**. Продолжение без подтверждения возможно при явном включении соответствующей галки. Настройку порога можно выключить и использовать прежний процесс привязки.

Это **payment threshold**, не `spend_cap`, не лимит кабинета или карты. Meta может ограничивать сумму, отклонять запрос или повышать эффективный порог постепенно. Порог не гарантирует строгий максимум задолженности или размера платежа. Ввод 100 при текущих 2 не означает, что Meta немедленно разрешит 100.

Адаптер поддерживает однозначно распознанный штатный диалог на английском языке (`locale=en_US`). При изменении интерфейса он прекращает операцию, а не нажимает произвольный Save. Неподтверждённый API записи не заменён выдуманной мутацией.

Основания: [официальный SDK Meta, AdAccount api_update](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/adobjects/adaccount.py) содержит `spend_cap`, но не подтверждённый метод записи payment threshold; точные подписи диалога предоставлены пользователем. [Официальная справка Meta](https://www.facebook.com/business/help/1342874532544030) требовала входа и не была доступна для чтения. Её содержание не использовалось как подтверждение работы адаптера.

## Проверка и разработка

```sh
pnpm install --frozen-lockfile
pnpm run build
pnpm test
```

Модули `src/catalog-guard.js` и `src/payment-threshold.js` встраиваются в `index.html` командой сборки. Закладке не нужны внешние модули. Установочные ссылки кодируют JavaScript, сохраняя переносы строк и комментарии.

Проверены синтаксис трёх bookmarklet, установка ссылок, сценарии отказов и валют, удаление и Rename с поддельными сетевыми ответами. **Живой тест изменения порога в Facebook не выполнялся**: тесты адаптера используют синтетический DOM по описанию диалога, а не реальный снимок Meta. Привязка/выпуск карт, платежи и удаления в живых аккаунтах при разработке не запускались. Тесты не гарантируют доступность внутренних Meta/LeadingCards API в конкретном аккаунте.

Не размещайте в исходниках токены, cookies или данные карт. GitHub Pages публикует `main / root`.
